# Logging Architecture & Auditing Reference

`vision-mission` implements structured database-backed logs alongside standard framework files to track automated crawler ingestion, deduplication gates, and administrative modifications.

---

## 1. Database-Backed Structured Logs

For traceability, operations are logged directly to the database:

### A. Scraping Logs (`scraping_logs`)
* **Purpose**: Records crawler run metrics.
* **Fields**: `scraping_source_id`, `status` (success, failed, quarantined), `items_found`, `error_message` (e.g. schema error notifications), `raw_payload`.

### B. Duplicate Audit Logs (`duplicate_audit_logs`)
* **Purpose**: Records items blocked by deduplication filters.
* **Fields**: `master_job_post_id` (the canonical record), `detection_method` (fingerprint, fuzzy, title_variant), `similarity_score`, `incoming_fingerprint`, `raw_payload`.

### C. AI Audit Logs (`ai_audit_logs`)
* **Purpose**: Tracks structured JSON fields generated by Gemini/OpenAI.
* **Fields**: `scraping_source_id`, `raw_text` (unstructured source text), `extracted_json`, `confidence_scores` (breakdown of scores per field), `overall_score`, `status` (passed, failed_confidence).

### D. Administrative Audit Logs (`audit_logs`)
* **Purpose**: Tracks dashboard setting edits and data wipes.
* **Fields**: `user_id`, `action`, `model_type`, `model_id`, `payload`, `ip_address`.

---

## 2. Standard Text Logging & Pail Integration

* **Standard Log file**: Writes details to `storage/logs/laravel.log` using standard facade methods (e.g. `Log::info()`, `Log::error()`).
* **Console Tailing via Pail**: 
  * The project includes the `laravel/pail` package.
  * Developers can stream errors and telemetry updates directly in the terminal in real-time using:
    ```bash
    php artisan pail
    ```
  * Pail captures logs from web requests, scraper crons, and Horizon queue threads into a single console stream.
